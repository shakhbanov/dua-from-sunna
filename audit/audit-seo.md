## 4. Три критические проблемы (P1)

### P1-01 · Двадцать проиндексированных URL Корана отдают 404 без возможности редиректа

Коммит `9419908` перевёл коллекцию Корана с тематических слагов на слаги по сурам. Прежние URL были живыми, стояли в sitemap, были в ссылках с главной и отправлялись через IndexNow.

```
GET /dua-iz-korana/dua-o-blage-v-oboikh-mirakh/   → 404
GET /en/quran-duas/duas-for-parents/              → 404
GET /dua-iz-korana/dua-iz-sury-al-fatiha/         → 200   (замена)
```

Наличие старых URL в ссылках подтверждено по коммиту `gh-pages` `d37fbb5`: 288 ссылок с главной, включая снятые тематические слаги. В текущей сборке `dist/dua-iz-korana/` содержит 37 каталогов по сурам и ноль тематических.

**Почему это срочно.** Каждый день в статусе 404 — это распад накопленных сигналов. Окно на восстановление закрывается, как только Google выбросит URL из индекса.

**Отдельно о самой реструктуризации:** переход с тематических URL на URL по сурам — **обоснованное редакционное решение**. Порядок мусхафа является канонической организацией коранического материала, а слаги по сурам стабильнее в долгую. Проблема не в решении, а в том, что оно уехало в продакшен без миграционного пути.

### P1-02 · Слой редиректов отсутствует, и текущий хостинг не может его дать

Деплой идёт через `peaceiris/actions-gh-pages@v4` на GitHub Pages — статическая отдача файлов. Ни `_redirects`, ни `netlify.toml`, ни `vercel.json` в репозитории нет. Единственный механизм — `public/404.html`.

Следствия: 301 невозможен, `X-Robots-Tag` недоступен, HSTS не выставить, `cache-control` не настроить. **P1-01 — первый случай проявления этой проблемы, а не единичный инцидент.** Любое будущее изменение слага уничтожает сигналы предшественника безвозвратно.

### P1-03 · Граф внутренних ссылок схлопнулся в одну звезду

Измерено на всех 372 страницах.

```
ИСХОДЯЩИЕ ССЫЛКИ                     ВХОДЯЩИЕ ССЫЛКИ
  2 ссылки  → 339 страниц              0 входящих →   6 страниц  ← сироты
  7–37      →  32 страницы (хабы)      1 входящая →  50 страниц
  340       →   1 страница (главная)   2 входящих → 296 страниц

ГЛУБИНА ОТ /                         Достижимо от /:  341 / 372
  уровень 0 →   1 страница            Недостижимо:      31
  уровень 1 → 340 страниц             Тупиков:           0
```

**Уровня 2 не существует.** Граф — это звезда: один хаб, 340 лучей, ноль рёбер между лучами.

**Первопричина — одна строка.** `components/Sidebar.tsx:171`, основная навигация по 134 главам:

```tsx
const ChapterRow: React.FC<RowProps> = ({ chapter, language, collection, isCurrent, onSelect }) => {
  return (
    <button onClick={() => onSelect(chapter.id)}>      // ← краулер не может перейти
```

Введено коммитом `e8f36d7` «Clear every react-doctor finding: 65 → 100». **Семьюдесятью строками выше тот же самый коммит использует правильный паттерн** для переключателя коллекций:


`RouteLink` (`src/router/RouteLink.tsx`) рендерит настоящий `<a href>` и перехватывает клик для SPA-навигации. Он уже импортирован в `Sidebar.tsx`. Исправление — использовать его и в `ChapterRow`.

**Шесть страниц-сирот с нулём входящих ссылок:**

Кликабельной связи между русским и английским деревьями нет: переключатель языка — это `<button onClick={() => onSelectLanguage(l)}>`. | **P2-05** | `og:type=website` на всех 372 страницах | Включая главы. Нет `article:published_time` / `article:modified_time` |
| **P2-06** | `http://` отдаёт 200 без редиректа на HTTPS | Плюс `shakhbanov.github.io/dua-from-sunna/` → 301 на **`http://`**, высаживая краулер на незащищённый origin. HSTS отсутствует |
| **P2-07** | Инфраструктура доверия издателя отсутствует полностью | Нет About, автора, редакционной политики, политики исправлений, контактов, дат публикации и обновления |

### Почему P2-07 важнее, чем кажется

Это религиозные рекомендации — мольбы, которые люди произносят и по которым действуют, с переводами, которые должны быть точны относительно арабского оригинала. Google в оценке качества сильно взвешивает вопрос «кто отвечает за этот контент и какова его квалификация» для материалов с реальными последствиями. AI-движки всё чаще требуют идентифицируемого авторства, прежде чем цитировать источник.

У сайта **сильное происхождение контента**: каждое дуа несёт ссылку на хадис или на суру и аят, и они дедуплицируются в `Article.citation`. У сайта **нулевое происхождение издателя**: нигде не сказано, кто составил сборник, кто выполнил перевод, кто сверил его с арабским и как сообщить об ошибке.

**Это решение владельца, а не инженерная задача.** Кого называть, какую квалификацию заявлять, есть ли научный рецензент — это нельзя выдумать, и в отчёте это помечено как решение, а не как тикет.

## 7. Системная причина

Находки P1-01, P1-03, P1-04 и P1-05 **все были внесены обычными, добросовестными коммитами**: один улучшал модель контента, другой доводил `react-doctor` до 100. Ни один не был небрежным.

Они уехали в продакшен, потому что **в CI нет ни одной проверки SEO-инвариантов**. Текущий гейт в `.github/workflows/deploy.yml`:

```bash
test -f dist/index.html
test -f "dist/slova-pominaniya-pri-probuzhdenii-oto-sna/index.html"
test -f "dist/en/supplications-upon-waking-up/index.html"
grep -q "اَلْحَمْدُ\|الْحَمْدُ" "dist/slova-pominaniya-pri-probuzhdenii-oto-sna/index.html"
grep -q "hreflang=\"en\"" "dist/slova-pominaniya-pri-probuzhdenii-oto-sna/index.html"
```

Замысел правильный — проверяется, что пререндер выдал настоящий арабский текст и hreflang, а не пустую оболочку. Но покрыто **2 файла из 372**, и ни один из сломавшихся инвариантов не проверяется.

| Находка | Внесена коммитом | Проверка, которая её поймала бы |
|---|---|---|
| P1-01 — 20 URL в 404 | `9419908` | Диф sitemap против предыдущего деплоя |
| P1-03 — схлопывание графа | `e8f36d7` | Достижимость по графу ссылок |
| P1-04 — 6 сирот | `e8f36d7` | Детекция страниц-сирот |
| P1-05 — 31 недостижимая | `e8f36d7` | Обход в ширину от `/` |
| P2-01 — два `<h1>` | было ранее | Проверка количества `<h1>` |

**Это и есть настоящая системная проблема.** Точечные исправления лечат симптомы; тестовый набор предотвращает рецидив. Восемь предлагаемых проверок описаны в [`seo-audit/AUTOMATION.md`](../seo-audit/AUTOMATION.md) — все выполняются локально по `dist/`, без сети и без новых зависимостей.

## 9. Финальный вердикт

### Может ли текущая архитектура масштабироваться до 100 000+ статей без системного SEO-долга?

# НЕТ

Не потому, что код плохой — таблица маршрутов, модель данных и архитектура canonical сделаны действительно хорошо и в основном пережили бы миграцию. Ответ «нет», потому что **четыре потолка носят структурный характер, и все четыре достигаются задолго до 100 000**.

**1. Хостинг — жёсткий потолок.** GitHub Pages не даёт редиректов, управления заголовками, `X-Robots-Tag`, и имеет мягкий лимит около 1 ГБ. При 100 тыс. страниц по ~57 КБ один только HTML — **около 5,7 ГБ**. P1-01 уже показал, чего стоит отсутствие редиректов на 372 страницах.

**2. Топология навигации — жёсткий потолок.** Главная ссылается на каждую главу по отдельности: **340 ссылок сегодня**. Это O(n) на страницу. При 100 тыс. статей главной понадобилось бы 100 000 ссылок, а её текущие 187 КБ превратились бы в ~50 МБ. У графа нет глубины (замерено: `{0:1, 1:340}`), а значит нет и иерархии для распределения краулингового бюджета.

**3. Sitemap — жёсткий потолок на 50 000.** Один плоский файл, полностью перегенерируемый каждой сборкой, без sitemap index и без шардирования. Лимит в 50 000 URL пробивается ровно на половине целевого масштаба.

**4. Клиентский бандл — неограниченный рост.** 319 КБ gzip статически импортируют весь корпус. Растёт линейно с архивом. При 100 тыс. статей это уже не проблема производительности, а неработающий сайт.

### Что потребовалось бы для «ДА, ПРИ УСЛОВИЯХ»

Хостинг с редиректами и управлением заголовками. Иерархическая навигация «главная → хабы → подхабы → статьи» с постраничными листингами и без полного индекса на любой отдельной странице. Sitemap index над шардами по коллекциям и языкам с настоящим поурловым `lastmod`. Данные страницы в самой странице, без корпусного бандла. Редакционная модель с авторами, датами, ревизиями и статусами. Набор проверок из [`seo-audit/AUTOMATION.md`](../seo-audit/AUTOMATION.md), блокирующий деплой.

### Честная оценка

На своём фактическом размере — **372 страницы** — сайт в хорошей форме. Canonical безупречны, sitemap точен, заголовки и описания уникальны на 100%, hreflang образцовый, контент полностью пререндерится и несёт реальные ссылки на источники.

Оценку 58 из 100 тянут вниз три вещи, которые чинятся дёшево (ссылочность, заголовки, выдуманные схемы), и одна действительно дорогая — инфраструктура доверия издателя.

Архитектура адекватна кураторскому справочному корпусу на несколько сотен или тысяч страниц, и никаких признаков намерения стать издателем на 100 тыс. статей в проекте нет. **Потолки масштабирования стоит знать, но не обязательно проектировать вокруг них заранее. Срочная работа — это Фазы 0 и 1; остальное — вопрос амбиции.**
